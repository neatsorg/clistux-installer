# 仕様書(下書き)

CLIP STUDIO PAINT(以下 CSP)を Linux の Wine で使うための環境を、1つのコマンドで作るインストーラの仕様。
この文書が実装の正となる。他のインストーラは下調べに使ってよいが、コードや文章は写さない(「方針」)。

- 状態: 下書き(2026-11-13)
- 「要調査」と書いたところは、まだ自分で確かめていない。確かめたら、調べた日と結果を書き足す。

## 目的

- 日本語環境の利用者が、今日的な Wayland のデスクトップ(COSMIC・KDE Plasma・GNOME)で、CSP を Windows に近い使い勝手で使えるようにする。
- 日本語入力(fcitx5 / IBus)、ペンタブレットの筆圧、CLIP STUDIO TABMATE を、追加の手作業なしで使えるようにする。
- CSP のバージョンアップに追随し続ける。作者自身が日常的に CSP を使う環境(CachyOS、COSMIC)を基準にする。

## 対象と非目標

| 対象 | 内容 |
|---|---|
| CPU・OS | x86_64 の Linux。まずは Arch 系(CachyOS など)。他のディストリビューションは要望に応じて |
| デスクトップ | Wayland のセッション(CSP 自体は XWayland で動く)。COSMIC を最初に、次に KDE Plasma・GNOME |
| CSP | 公式サイトから入手する Windows 版。どのバージョンから対応するかは要調査 |
| 言語 | 文書・メッセージは日本語が主。英語を併記する |

非目標:

- CSP 本体やライセンスを再配布しない。CSP は利用者が公式サイトから入手し、ライセンスも利用者が CELSYS と結ぶ。
- Wine 全般のインストーラにしない。CSP 専用に絞る。
- Flatpak・Snap の Wine や、Proton(Steam)の上では動かさない(当面)。

## 方針

### 独立した実装にする

- 既存の CSP 用インストーラ(CSPenguin など)のコード・文章・同梱ファイル(dll、フォント、パッチ、画像)は流用しない。
  ライセンスが明記されていないため。
- 一方、誰が調べても同じになる事実(CSP が必要とするランタイム、どのレジストリ値が何に効くか、など)は、
  既存のインストーラを下調べに使って拾ってよい。拾ったものは実機で確かめ、自分のコードと言葉で書く。
  確かめた方法と日付を `docs/research.md` に残す。
- 既存のインストーラの作者が判断で選んだ設定(速度のために何かを無効にする、など)は事実ではないので、
  効果と副作用を自分で確かめてから、採るかどうかを決める。
- 下調べに使ったプロジェクトは、README の謝辞に書く。

### ライセンス

- Wine へのパッチと、それを当ててビルドした Wine は、Wine と同じ LGPL-2.1-or-later。配るときはソースとパッチを一緒に公開する。
- インストーラ本体と文書のライセンスは未決(「未決事項」)。

### 作りの原則

- **何度実行しても同じ結果になる**(冪等)。途中で失敗しても、もう一度実行すれば続きから直る。
- **root が必要な操作は分けて、何をするかを表示してから行う**(udev ルールの配置など)。黙って sudo しない。
- **利用者の既存の設定を黙って上書きしない**。上書きするときは退避して、退避先を表示する。
- **常駐プロセスを増やさない**。必要なら、機器の接続に連動して起動・終了する仕組みにする。
- ログはファイルに残し、失敗したときはその場所を表示する。

### 設計の三本柱(2026-11-15、作者の指示)

1. **CSP の更新に追随しやすくする。**
   - 設定は CSP の版ではなく、exe の名前(`CLIPStudioPaint.exe`・`CLIPStudio.exe`・`msedgewebview2.exe`)に結びつける。
   - 設定を入れる手順(`apply_settings`)を独立させ、何度実行しても同じ結果にする。CSP の導入・更新のたびに実行する。
   - CSP の場所は、版を含むパスを決め打ちにせず、プレフィックスの中から探す。
   - CSP の更新は「新しい公式インストーラを実行し、設定を入れ直す」の1コマンド(`clistux update-csp`)。
   - 動作を確かめた CSP の版の一覧(`data/tested-versions`)を持ち、一覧に無い版では「未確認の版」と知らせる(止めない)。
2. **頒布を前提に、PC に不慣れな人にもわかるようにする。**
   - 手順に番号を付けて表示する(`[3/7] Wine を準備しています`)。専門用語を避け、必要なら一言の説明を添える。
   - 足りないものは、そのディストリビューションの導入コマンドの形で示す。
   - CSP のインストーラは「ダウンロード」フォルダーから自動で探す。
   - root が必要な操作や、利用者の設定ファイルへの追記は、何をするかを説明し、確認してから行う。
   - 失敗したら、ログの場所と次にすること(`clistux doctor`)を表示する。
3. **COSMIC 向けの対処を含める。** Wine のパッチ3本(要件 2)、作業領域のヘルパー(要件 5)、`XMODIFIERS` の書き場所(要件 6)。

## 要件

### 1. 前提の確認

- 必要なコマンド・ライブラリがあるかを調べ、足りなければディストリビューションごとの導入コマンドを表示する(自動では入れない)。
  一覧は要調査(32bit ライブラリの要否、GStreamer、Vulkan など)。
- セッションの種類(Wayland / X11)とデスクトップの種類を調べ、以降の手順の分岐に使う。
- ディスクの空き容量を確かめる(必要量は要調査)。
- `/dev/ntsync` が読み書きできるかを確かめる。Wine 11 は、これがあれば同期に ntsync を使う(esync・fsync の設定や、
  ファイル数の上限の変更は要らない)。無ければ、カーネルの版(6.14 以降)とモジュールの読み込みを案内する。

### 2. Wine の入手

- パッチ入りの Wine を、このプロジェクトの GitHub Releases から入手する。ビルドは GitHub Actions で行い、ソースとパッチを同じリリースに付ける。
- 基にする Wine のバージョンは1つに固定し、上げるときは CSP の動作を確かめてからにする。
- 当てるパッチ(作者が書いたもの):
  - winex11:所有者のあるポップアップ(メニュー・ツールチップ)を、ウィンドウマネージャの管理外にする。COSMIC でメニューの位置がずれる問題への対処
  - winex11:自前で枠を描くウィンドウの最大化を正しく扱う
  - win32u:最大化したウィンドウの枠を作業領域に収める
- 入手したファイルはチェックサムで確かめる。

### 3. プレフィックスの作成

- CSP 専用のプレフィックスを1つ作る(既定は `~/.local/share/<名前>/prefix` など。場所は未決)。
- Windows のバージョン設定、CSP が必要とするランタイム(Visual C++ ランタイム、WebView2 など)の導入。要件の洗い出しは要調査。
- 日本語のフォント(CSP の画面の文字化け・豆腐対策)。何が必要かは要調査。フォントを同梱する場合は、再配布できるライセンスのものに限る。

### 4. CSP 本体

- 公式サイトのインストーラを利用者に取得してもらうか、公式の配布 URL から取得する。どちらにするかは、利用規約を確かめてから決める(要調査)。
- インストーラを Wine で実行する。サイレントインストールができるかは要調査。
- CSP のバージョンアップのときは、同じ手順で上書きインストールできるようにする。

### 4.5 Windows のバージョンの見せ方(2026-11-15 に確認)

- `CLIPStudio.exe`:Windows 8.1(`HKCU\Software\Wine\AppDefaults\CLIPStudio.exe\Version=win81`)。WebView2 をウィンドウ方式で使わせるため
  (Windows 10 では CompositionController を使い、Windows の非公開のインターフェースが要る)。
- `msedgewebview2.exe`:Windows 7。Chromium に DirectComposition を使わせないため。
- `CLIPStudioPaint.exe`:Wine の初期値(Windows 10)のまま。8.1 にすると「動作保証対象外の OS」の警告が出る。
  CSP 本体の中の WebView2 の画面(初回のお知らせなど)は白いままだが、閉じられる。

### 4.5.1 WebView2(2026-11-15 に確認)

- CSP 5.1.5 のインストーラが入れる WebView2(115)は、Wine ではブラウザが起動中に止まり、Web の画面が白くなる。135・157 では表示できる。
- Microsoft が配っている版固定の WebView2(Fixed Version)の最新版を、ダウンロードページから URL を読み取って入手し、プレフィックスの
  `C:\Program Files\clistux\WebView2\<版>` に展開する。公式に配られているのは最新の数版だけなので、版を決め打ちにしない。
- `wv2check.exe`(このプロジェクトの道具)でページを1枚表示できるかを確かめ、通った版だけを使う。前の版を1つ控えとして残し、
  `clistux webview2 --previous` で戻せる。
- CSP と CLIP STUDIO に使わせる版は、レジストリのポリシー
  `HKLM\Software\Policies\Microsoft\Edge\WebView2\BrowserExecutableFolder`(値の名前は exe の名前)で指定する。起動の経路を問わずに効く。
- 未確認:動かない版(115 など)を wv2check が失敗と判定すること(115 の固定版は公式に無い)。

### 4.6 不要なもの(2026-11-15 に確認)

- dotnet48、Wine Mono、Wine Gecko は入れない(CSP と CLIP STUDIO に .NET のプログラムは無く、無効のままで動いた)。

### 4.7 日本語フォント

- `HKCU\Software\Wine\Fonts\Replacements` に、Windows の日本語フォント名(MS UI Gothic、MS ゴシック、メイリオ、Meiryo UI、
  游ゴシック、Yu Gothic UI、MS 明朝、游明朝 など。英語名と日本語名の両方)から、Linux 側の日本語フォントへの置き換えを入れる。
  値は `REG_MULTI_SZ` の候補の並び(例:Noto Sans CJK JP、IPAex ゴシック、…)。元のフォントがあれば置き換えは使われない。
- インストール時に、候補のどれかが入っているかを確かめ、無ければ導入の方法を案内する。
- **ゴシック体と明朝体を分ける**:ゴシック体の名前(MS UI Gothic、MS ゴシック、MS P ゴシック、メイリオ、Meiryo UI、游ゴシック、
  Yu Gothic UI)はゴシック体の候補へ、明朝体の名前(MS 明朝、MS P 明朝、游明朝)は明朝体の候補へ置き換える。明朝体の候補が
  1つも無ければ、ゴシック体で代用する。(winetricks の `cjkfonts` を入れたとき、CSP のメニューが明朝体になった。)
- **候補は日本語の字形の書体名で決め打ちにする**:fontconfig の「日本語に対応」(`:lang=ja`)には、Noto Sans CJK KR のような
  ほかの地域の版も含まれ、実際に選ばれた。候補の例(上から順に優先):
  - ゴシック体:Noto Sans CJK JP、Source Han Sans JP、IPAex ゴシック(IPAexGothic)、BIZ UDP ゴシック、VL ゴシック
  - 明朝体:Noto Serif CJK JP、Source Han Serif JP、IPAex 明朝(IPAexMincho)、BIZ UDP 明朝
- winetricks の `cjkfonts` は使わない(起動が毎回約 9 秒遅くなる。research.md)。
- Windows のフォントが無い環境では、置き換えだけで日本語は表示される(2026-11-15 確認)。ただし Wine のままでは、メニュー
  (Tahoma + 横幅の指定 + フォントリンク)の日本語が横に約半分に縮む。`wine/patches/unix/win32u-linked-font-width.patch` で直す
  (リンク先のフォントに、元のフォントの縦横比を使う)。Windows のフォントがある環境では、修正の前後で見た目は変わらない。
  この修正を入れた `win32u.so` を配る(`wine/build-unix.sh`)。

### 4.8 ほかの方法で入れた CSP からの引き継ぎ(2026-11-16 に確認)

- 探す場所:CSPenguin(`~/.wine-csp`)、素の Wine(`~/.wine`、`~/.local/share/wineprefixes/*`)、Bottles(Flatpak とふつうの版)、
  Lutris(`~/Games/*`)、PlayOnLinux。`--from` で場所を指定できる。
- 写すもの:`AppData\Roaming\CELSYSUserData`(ツール・ブラシ・ワークスペース・ショートカット・素材・TABMATE の割り当て)と、
  `AppData\Roaming\CELSYS`(環境設定・ウィンドウの配置)。
- 写さないもの:キャッシュ(`CacheData`)・一時ファイル、認証やライセンスに関わるもの(`Certification`・`promenade`)。引き継いだ後に、もう一度ログインしてもらう。
- 新しい環境にすでにある設定は、上書きせずに `…before-migrate-<日時>` に移す。元の環境は変更しない(消すのは元のツールに任せ、消してよいと案内する)。
- 作品:プレフィックスの「ドキュメント」は、ふつうは Linux の `~/ドキュメント` へのリンクなので、何もしなくても見える。元の環境の「ドキュメント」が
  環境の中のフォルダーなら、`~/ドキュメント` の下に写す。
- CSP は設定を終了時に保存する。引き継ぎは、元の CSP も新しい CSP も閉じてから行う(動いていれば止まる)。
- 確認:CSPenguin の 5.1.2 から 5.1.5 へ、TABMATE の割り当てを含めて引き継げた。

### 5. 起動

- 起動用のスクリプトを1つ置き、環境変数をそこに集める。
- `.desktop` ファイルを置き、アプリのメニューから起動できるようにする。`.clip` ファイルの関連付けも行う。
- 起動前に、COSMIC と Hyprland が X11 に作業領域を知らせない問題への対処(作業領域ヘルパー)を実行する。
- 起動が遅い原因と対策は要調査(ファイルの先読み、wineserver の常駐など)。常駐を増やす対策は、効果を測ってから採る。

### 6. 日本語入力

- `XMODIFIERS` を設定して、Wine を動作中の fcitx5 / IBus につなぐ。
- COSMIC では、ログインの環境変数(`.zprofile` など)に書く必要がある。デスクトップごとに書く場所を調べて案内する。
- 動作確認:CSP のテキストツールで日本語を入力し、変換候補の位置も確かめる。

### 7. ペンタブレット

- 筆圧は Wine の wintab(X11 の XInput)経由で取る。
- 複数のモニタを使い、ペンタブレットのモニタが画面全体の左上にない配置では、CSP の「タブレットモード」だと位置がずれる。
  「マウスモード」を案内する(位置はカーソルから、筆圧だけ wintab から取る)。
- CSP の起動中にモニタの配置を変えない(Wine が起動時の配置を持ち続ける)ことを案内する。

### 8. CLIP STUDIO TABMATE

2026-11-12〜13 に作者の環境で確かめた方式。

- winebus を hidraw 経路にする:プレフィックスで `Enable SDL=0`・`DisableInput=1`。Wine 11.4 では、この組み合わせのとき、ゲームパッドとジョイスティックを hidraw から作る。
- TABMATE の hidraw にだけ、ログイン中の利用者の読み書き権限を付ける udev ルールを置く(`TAG+="uaccess"`、Bluetooth で VID/PID が `0A5C:8502` の HID 機器だけ)。root が必要。
- PlugPlay サービスを有効(自動起動)にする。無効だと機器の追加・削除の通知が CSP に届かず、CSP の起動後につないだ TABMATE を拾えない。
- 案内すること:
  - ペアリングは Bonded: yes になるように行う(BlueZ の初期設定では、ボンディングしていない HID 機器は拒否される)。
  - 10分操作しないとスリープする。CLIP STUDIO ボタン以外のボタンで復帰し、TABMATE から再接続してくる。
- TABMATE 2(Bluetooth LE)は未確認。

### 9. 更新・削除・診断

- `update`:Wine とパッチ、起動スクリプト、設定を最新にする。利用者が変えた設定(PlugPlay など、このインストーラが決めた値)を、元に戻さない。
- `uninstall`:このインストーラが置いたものを一覧して消す。プレフィックス(CSP の作品や設定を含む)は、確認してから消す。
- `doctor`:よくある不具合の原因を調べて表示する。例:取り残された Wine のプロセス、TABMATE の hidraw の権限、ボンディングの状態、`XMODIFIERS` の有無。

## 構成案

```text
clistux/
├── install.sh          # 入口。サブコマンド: install / update / uninstall / doctor
├── lib/                # 手順ごとのスクリプト(前提の確認、Wine、プレフィックス、CSP、統合)
├── wine/
│   ├── patches/        # Wine へのパッチ(LGPL-2.1-or-later)
│   └── build.sh        # GitHub Actions とローカルで使うビルドスクリプト
├── integration/
│   ├── udev/           # TABMATE の udev ルール
│   ├── desktop/        # .desktop・MIME
│   └── workarea/       # COSMIC・Hyprland 用の作業領域ヘルパー
└── docs/               # 仕様書、調査メモ、利用者向けの説明(日本語・英語)
```

## マイルストーン

1. **作者の日常の環境を、このインストーラで作り直せる。** 既存のプレフィックスは使わず、新しい場所に作る。
2. 作者の別の PC(別のディストリビューション・デスクトップ)でも同じ手順で動く。
3. 公開する。README に、対応環境・既知の問題・CSP のライセンスについての注意を書く。
4. CSP の新しいバージョンが出るたびに動作を確かめ、結果を表にして残す。
